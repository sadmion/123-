# Docker 部署与维护手册

> **本文档是 Docker 部署的主操作手册。**
> 桌面版（exe）的故障处理见根目录的 `打不开怎么办.md` 等文档——**Docker 部署用不到那些工具**。

---

## 一、Docker 版与桌面版的区别（重要）

Docker 容器启动时由 `docker/entry.py` 做了一层适配，**已经规避了桌面版的常见坑**：

| 桌面版（exe）的坑 | Docker 版为何不会遇到 |
|---|---|
| 双击没反应 / 浏览器打不开<br>（数据目录不存在导致程序退出） | `entry.py` 里有 `os.makedirs(DATA_DIR, exist_ok=True)`，**启动时强制创建数据目录**；且 `LB_DATA_ROOT` 由 compose 显式指定 |
| 只能本机访问（监听 127.0.0.1） | `entry.py` 把监听地址改写为 `0.0.0.0`，**局域网可直接访问** |
| 桌面窗口/浏览器拉不起来 | 设置 `LB_BROWSER=1` 跳过 pywebview，屏蔽 `webbrowser` |
| Windows 专有 DLL 依赖 | 容器内直接跑抽出的字节码，不加载任何 `.dll/.pyd` |

**因此以下桌面版专用工具在 Docker 部署中不需要使用**：

| 工具 | 用途 | Docker 是否需要 |
|---|---|---|
| `启动修复.py` | 修数据目录配置 | ❌ 不需要 |
| `打不开怎么办.md` | 桌面版启动排查 | ❌ 不需要 |
| `影库瘦身.py` | 拆分大影库（缓解内存） | ⚠️ **可选**（见第四节） |
| `断点修复.py` | 修旧格式断点 | ⚠️ **遇到才用** |
| `追加影库崩溃-诊断报告.md` | 桌面版内存分析 | ❌ 不需要 |
| `提取失败-skipped-修复.md` | 桌面版断点问题 | ⚠️ 遇同样报错可参考 |

## 二、部署

### 方式一：拉取现成镜像（最省事）

镜像由 GitHub Actions 自动构建。**前提：GHCR 包需设为 Public**，否则会 `unauthorized`。

```bash
# 在一个空目录里创建 docker-compose.yml，内容见下方「极简配置」
docker compose up -d
```

### 方式二：本地构建（不依赖 GHCR）

```bash
git clone https://github.com/sadmion/123-.git
cd 123-
docker compose up -d --build
```

首次构建约 2~5 分钟。仓库已含 exe，克隆后可直接构建。

### 极简配置（只想要一个能跑的 compose）

```yaml
services:
  pan123-library:
    image: ghcr.io/sadmion/pan123-library:latest
    container_name: pan123-library
    restart: unless-stopped
    ports:
      - "5890:5890"
    environment:
      TZ: Asia/Shanghai
      LB_BROWSER: "1"
      LB_DATA_ROOT: /data
    volumes:
      - ./data:/data
```

### 验证部署成功

```bash
docker compose ps                    # 期望 Up (healthy)
docker compose logs -f               # 看到访问地址即正常
curl http://127.0.0.1:5890/api/login/status    # 期望 {"logged": false}
```

## 三、日常运维命令

```bash
# 查看状态与日志
docker compose ps
docker compose logs -f --tail 100

# 重启
docker compose restart

# 停止并删除容器（data/ 数据不受影响）
docker compose down

# 更新到最新镜像
docker compose pull && docker compose up -d

# 用本地代码重新构建
docker compose up -d --build

# 换端口（宿主机 8080）
LB_PORT=8080 docker compose up -d

# 进容器排查
docker compose exec pan123-library sh
docker compose exec pan123-library ls -la /data

# 查看资源占用
docker stats pan123-library
```

## 四、数据与影库

### 目录结构

```
<部署目录>/
├── docker-compose.yml
└── data/                              # ← 挂载到容器 /data
    ├── 秒传文件导入或追加/             # 影库 JSON 放这里，程序自动加载
    ├── 秒传文件导出/                   # 导出的秒传文件
    ├── 记录数据存放目录【勿动】/        # 登录凭据、配置
    ├── _checkpoints/                   # 提取断点（自动生成）
    └── logs/server.log                 # 运行日志
```

### 加影库

```bash
# 方式 A：把文件拷进挂载目录（程序每 3 秒自动扫描）
cp "你的影库.123fastlink.json" ./data/秒传文件导入或追加/

# 方式 B：在网页上点「追加影库」上传
```

### 备份 / 迁移

```bash
# 整个 data/ 拷走即可（含登录态、影库、断点、历史）
tar czf backup-$(date +%F).tar.gz data/
```

**注意**：`data/记录数据存放目录【勿动】/.login.json` 含 123 云盘登录凭据，备份文件妥善保管。

### 影库太大的处理（仅在容器内存不足时才需要）

如果影库特别大导致容器 OOM（`docker compose logs` 里能看到
`Killed` 或容器反复重启），用瘦身工具拆分：

```bash
# 在宿主机上执行（需要 Python 3.8+）
python 影库瘦身.py "./data/秒传文件导入或追加/大影库.json" --info
python 影库瘦身.py "./data/秒传文件导入或追加/大影库.json" --split-by-dir 50000

# 移走原大库，放入拆分结果
mkdir -p ./data/秒传文件导入或追加/_old
mv "./data/秒传文件导入或追加/大影库.json" ./data/秒传文件导入或追加/_old/
cp 瘦身输出/*.json ./data/秒传文件导入或追加/

docker compose restart
```

> **容器内存限制**：如需限制，在 compose 里加：
> ```yaml
>     deploy:
>       resources:
>         limits:
>           memory: 4G
> ```
> 建议值 ≥ 4G；若加载后仍 OOM，用上面的瘦身方案。

## 五、故障排查

| 现象 | 原因与处理 |
|---|---|
| `docker: command not found` | 先装 Docker（NAS 在套件中心装 Docker/Container Manager） |
| 拉镜像报 `unauthorized` | GHCR 包默认私有 → 仓库页 `Packages` → `pan123-library` → `Package settings` → `Change visibility` → `Public` |
| `invalid reference format` | 镜像名别写成仓库名。正确是 `ghcr.io/sadmion/pan123-library`（`123-` 结尾连字符属非法名） |
| `manifest unknown` | 镜像还没构建成功，去 Actions 页确认；或改用 `--build` 本地构建 |
| 容器反复重启 | `docker compose logs` 看报错；多为端口冲突或 `/data` 无写权限 |
| 访问不了 | ①端口占用 `netstat -tlnp \| grep 5890`；②云服务器安全组未放行；③改了 `LB_PORT` 要用新端口 |
| 页面能开但搜不到内容 | 影库没放对位置。必须在 `data/秒传文件导入或追加/`（**容器内的 `/data`**，对应宿主机 `./data`） |
| 导出文件找不到 | 在 `data/秒传文件导出/` |
| 容器被 OOM 杀掉 | 影库过大 → 用第四节瘦身方案，或提高 `limits.memory` |
| NAS 上 `data/` 文件改不动 | 容器以 root 运行，执行 `sudo chown -R $(id -u):$(id -g) data` |
| 改了 `LB_PORT` 后访问不了 | 用新端口访问；同时确认 compose 已重新 `up` |

## 六、更新镜像的方式

### 何时需要重建镜像

| 变更 | 需要重建？ |
|---|---|
| 换了新的 exe（作者发新版 / 你重新打包） | ✅ **需要** |
| 改了 `docker/` 下的 Dockerfile、entry.py、extract_pyinstaller.py | ✅ **需要** |
| 只改了文档、加了工具脚本 | ❌ 不需要 |
| 只改了影库内容、配置 | ❌ 不需要 |

### 重建流程

```bash
# 方式 A：在部署机器上直接重建
git pull
docker compose up -d --build

# 方式 B：推 tag 让 GitHub Actions 自动构建
git tag -a v1.0.4 -m "V1.0.4"
git push origin v1.0.4
# 等 Actions 变绿后，在部署机器上：
docker compose pull && docker compose up -d
```

### 构建前自检（无需 Docker）

```bash
python docker/selfcheck.py
# 期望：13 项通过，0 项失败
```

## 七、安全提醒

- 工具**没有账号体系**，能访问端口就能使用其中的 123 云盘登录态。
  **仅限内网/家庭 NAS，不要直接映射到公网。**
- 确需外网访问，请加反向代理认证（Nginx + Basic Auth）或只走 VPN。
- 容器默认以 root 运行。如需更严格隔离，可在 compose 里加
  `user: "1000:1000"` 并确保 `./data` 属主对应。
- `.login.json` 保存登录凭据，**不要提交到公开仓库**（已在 `.gitignore` 排除）。
