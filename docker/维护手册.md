# 部署与维护手册

> **本文档是本项目的主操作手册。**
> 项目已全面转为「源码 + Docker」，不再分发桌面版 exe。

---

## 一、容器适配说明（重要）

`docker/entry.py` 是容器启动器，它把原本为 Windows 桌面环境编写的程序
适配到了容器里，**规避了这些坑**：

| 原有问题 | `entry.py` 如何解决 |
|---|---|
| 程序要求数据目录必须已存在，否则弹窗选择框并退出 | `os.makedirs(DATA_DIR, exist_ok=True)` **启动时强制创建**；`LB_DATA_ROOT` 由 compose 显式指定 |
| 只能本机访问（内部硬编码监听 127.0.0.1） | 把监听地址改写为 `0.0.0.0`，**局域网可直接访问** |
| 会尝试拉起桌面窗口/浏览器 | 设置 `LB_BROWSER=1` 跳过 pywebview，并屏蔽 `webbrowser` |
| 依赖平台专有二进制 | 容器内直接跑 `src/` 源码，不加载任何 `.dll/.pyd` |

程序入口为 `src/server.py`，静态资源（`index.html` / `style.css` / `app.js`）
与源码同放在 `src/` 目录。

## 二、部署

### 方式一：拉取现成镜像（最省事）

镜像由 GitHub Actions 自动构建。**前提：GHCR 包需设为 Public**，否则会 `unauthorized`。

```bash
# 在一个空目录里创建 docker-compose.yml，内容见下方「极简配置」
docker compose up -d
```

### 方式二：本地构建（不依赖 GHCR）

```bash
git clone https://github.com/sadmion/123-.git
cd 123-
docker compose up -d --build
```

首次构建约 2~5 分钟。仓库已含 `src/` 源码，克隆后可直接构建。

### 极简配置（只想要一个能跑的 compose）

```yaml
services:
  pan123-library:
    image: ghcr.io/sadmion/pan123-library:latest
    container_name: pan123-library
    restart: unless-stopped
    ports:
      - "5890:5890"
    environment:
      TZ: Asia/Shanghai
      LB_BROWSER: "1"
      LB_DATA_ROOT: /data
    volumes:
      - ./data:/data
```

### 验证部署成功

```bash
docker compose ps                    # 期望 Up (healthy)
docker compose logs -f               # 看到访问地址即正常
curl http://127.0.0.1:5890/api/login/status    # 期望 {"logged": false}
```

## 三、日常运维命令

```bash
# 查看状态与日志
docker compose ps
docker compose logs -f --tail 100

# 重启
docker compose restart

# 停止并删除容器（data/ 数据不受影响）
docker compose down

# 更新到最新镜像
docker compose pull && docker compose up -d

# 用本地代码重新构建
docker compose up -d --build

# 换端口（宿主机 8080）
LB_PORT=8080 docker compose up -d

# 指定本地构建的镜像标签（默认 latest）
LB_TAG=1.0.4 docker compose up -d --build

# 改用远程镜像（不在本地 build）
LB_IMAGE=ghcr.io/sadmion/pan123-library docker compose pull
LB_IMAGE=ghcr.io/sadmion/pan123-library docker compose up -d

# 进容器排查
docker compose exec pan123-library sh
docker compose exec pan123-library ls -la /data

# 查看资源占用
docker stats pan123-library
```

## 四、数据与影库

### 目录结构

```
<部署目录>/
├── docker-compose.yml
└── data/                              # ← 挂载到容器 /data
    ├── 秒传文件导入或追加/             # 影库 JSON 放这里，程序自动加载
    ├── 秒传文件导出/                   # 导出的秒传文件
    ├── 记录数据存放目录【勿动】/        # 登录凭据、配置
    ├── _checkpoints/                   # 提取断点（自动生成）
    └── logs/server.log                 # 运行日志
```

### 加影库

```bash
# 方式 A：把文件拷进挂载目录（程序每 3 秒自动扫描）
cp "你的影库.123fastlink.json" ./data/秒传文件导入或追加/

# 方式 B：在网页上点「追加影库」上传
```

### 备份 / 迁移

```bash
# 整个 data/ 拷走即可（含登录态、影库、断点、历史）
tar czf backup-$(date +%F).tar.gz data/
```

**注意**：`data/记录数据存放目录【勿动】/.login.json` 含 123 云盘登录凭据，备份文件妥善保管。

### 影库太大 / 容器内存不足

影库加载后会常驻内存（每条约 200 字节量级，74 万条约 150MB）。
若容器 OOM（`docker compose logs` 里能看到 `Killed` 或反复重启），
有两个方向：

**① 按目录拆分大影库**

把单个大 JSON 拆成多个小库，程序会分别加载：

```bash
# 用 Python 按目录字段拆分（示例：每 5 万条一个文件）
python - <<'EOF'
import json, os
src = "./data/秒传文件导入或追加/大影库.json"
d = json.load(open(src, encoding="utf-8"))
files = d.get("files", [])
os.makedirs("split", exist_ok=True)
step = 50000
for i in range(0, len(files), step):
    part = dict(d, files=files[i:i+step],
                totalFilesCount=len(files[i:i+step]))
    json.dump(part, open(f"split/大影库-{i//step+1}.json", "w", encoding="utf-8"),
              ensure_ascii=False)
print("已拆分", (len(files)+step-1)//step, "个文件")
EOF

# 移走原大库，放入拆分结果
mkdir -p "./data/秒传文件导入或追加/_old"
mv "./data/秒传文件导入或追加/大影库.json" "./data/秒传文件导入或追加/_old/"
cp split/*.json "./data/秒传文件导入或追加/"
docker compose restart
```

**② 放宽容器内存限制**

在 compose 的 service 下加：

```yaml
    deploy:
      resources:
        limits:
          memory: 4G
```
> 建议值 ≥ 4G；若加载后仍 OOM，用上面的瘦身方案。

## 五、故障排查

| 现象 | 原因与处理 |
|---|---|
| `docker: command not found` | 先装 Docker（NAS 在套件中心装 Docker/Container Manager） |
| 拉镜像报 `unauthorized` | GHCR 包默认私有 → 仓库页 `Packages` → `pan123-library` → `Package settings` → `Change visibility` → `Public` |
| `invalid reference format` | 镜像名别写成仓库名。正确是 `ghcr.io/sadmion/pan123-library`（`123-` 结尾连字符属非法名） |
| `manifest unknown` | 镜像还没构建成功，去 Actions 页确认；或改用 `--build` 本地构建 |
| 容器反复重启 | `docker compose logs` 看报错；多为端口冲突或 `/data` 无写权限 |
| 访问不了 | ①端口占用 `netstat -tlnp \| grep 5890`；②云服务器安全组未放行；③改了 `LB_PORT` 要用新端口 |
| 页面能开但搜不到内容 | 影库没放对位置。必须在 `data/秒传文件导入或追加/`（**容器内的 `/data`**，对应宿主机 `./data`） |
| 导出文件找不到 | 在 `data/秒传文件导出/` |
| 容器被 OOM 杀掉 | 影库过大 → 用第四节瘦身方案，或提高 `limits.memory` |
| NAS 上 `data/` 文件改不动 | 容器以 root 运行，执行 `sudo chown -R $(id -u):$(id -g) data` |
| 改了 `LB_PORT` 后访问不了 | 用新端口访问；同时确认 compose 已重新 `up` |

## 六、更新镜像的流程（**日常最主要的操作**）

部署方式是「拉取 GHCR 镜像」，所以**版本更新的核心就是让 CI 重建镜像**。

### 何时需要重建镜像

| 变更 | 需要重建？ |
|---|---|
| 改了 `src/` 下的源码 | ✅ **需要** |
| 改了 `docker/` 下的 Dockerfile、entry.py | ✅ **需要** |
| 只改了文档、加了工具脚本 | ❌ 不需要 |
| 只改了影库内容、配置、登录态 | ❌ 不需要 |

### 一键发布（改完源码后）

**第 1 步：改好 `src/` 下的源码**

改完保存即可；只改前端就替换 `src/` 下的 `index.html` / `app.js` / `style.css`。

**第 2 步：跑发布工具**

```bash
# 先预演一遍（不提交，看看会做什么）
python 发布新版本.py --version 1.0.4 --note "修复xx" --dry-run

# 确认无误后正式发布
python 发布新版本.py --version 1.0.4 --note "修复xx"
```

工具会自动完成：

1. 校验仓库状态（源码是否更新、能否连远程）
2. 跑 `docker/selfcheck.py` 构建自检（13 项，**不需要 Docker**）
3. 提交改动（提交信息规范化为「更新到 V1.0.4：修复xx」）
4. 打 tag `v1.0.4` 并推送 → **触发 GitHub Actions 重建镜像**

**第 3 步：等 CI 完成**

```
https://github.com/sadmion/123-/actions
```

约 1~3 分钟，变绿即镜像已发布。

**第 4 步：在 NAS 上更新**

```bash
docker compose pull && docker compose up -d
```

**第 5 步：验证**

```bash
curl http://127.0.0.1:5890/api/login/status     # 期望 {"logged": false}
```

### 手动流程（不想用脚本时）

```bash
git add -A
git commit -m "更新到 V1.0.4：修复xx"
git tag -a v1.0.4 -m "发布 V1.0.4"
git push origin main && git push origin v1.0.4
```

### 构建前自检（可选，建议保留）

```bash
python docker/selfcheck.py
# 期望：13 项通过，0 项失败
```

这个自检**不需要 Docker**，直接把 Dockerfile 里除 `pip install` 和镜像打包
之外的每一步真实跑一遍（上下文裁剪、源码与资源齐备、编译、模块导入、entry 适配逻辑、真实启动探活）。
自检不通过就别推 tag，省得等半天 CI 才发现问题。

### 回滚到旧版本

镜像按版本打了 tag，可以指定旧版本：

```bash
# 在 compose 里把 image 改成指定版本
#   image: ghcr.io/sadmion/pan123-library:1.0.3
docker compose up -d
```

## 七、安全提醒

- 工具**没有账号体系**，能访问端口就能使用其中的 123 云盘登录态。
  **仅限内网/家庭 NAS，不要直接映射到公网。**
- 确需外网访问，请加反向代理认证（Nginx + Basic Auth）或只走 VPN。
- 容器默认以 root 运行。如需更严格隔离，可在 compose 里加
  `user: "1000:1000"` 并确保 `./data` 属主对应。
- `.login.json` 保存登录凭据，**不要提交到公开仓库**（已在 `.gitignore` 排除）。
